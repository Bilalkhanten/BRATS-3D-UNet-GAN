# Data

## BraTS 2020 layout

The code reads the training release of BraTS 2020 as distributed by the organisers:

```
MICCAI_BraTS2020_TrainingData/
  name_mapping.csv                      # grade (HGG/LGG) per case
  BraTS20_Training_001/
    BraTS20_Training_001_t1.nii.gz
    BraTS20_Training_001_t1ce.nii.gz
    BraTS20_Training_001_t2.nii.gz
    BraTS20_Training_001_flair.nii.gz
    BraTS20_Training_001_seg.nii.gz
```

The data are not distributed with this repository; they must be requested from the BraTS organisers (see <https://www.med.upenn.edu/cbica/brats2020/data.html>).

## Labels and regions

The expert labels are 0 background, 1 necrotic and non-enhancing core, 2 oedema and 4 enhancing tumour. The network predicts
three **nested regions** with independent sigmoid outputs:

| Region | Labels | Channel |
| --- | --- | --- |
| WT whole tumour | 1, 2, 4 | 0 |
| TC tumour core | 1, 4 | 1 |
| ET enhancing tumour | 4 | 2 |

so that ET is contained in TC, which is contained in WT. Predictions are projected onto this nesting (`metrics.enforce_hierarchy`).

## Pre-processing

```bash
python scripts/prepare_data.py --root /data/BraTS2020 --cache cache --splits splits.json --workers 4
# or: bratsgan prepare --root /data/BraTS2020 --cache cache --splits splits.json --workers 4
```

For each case the four sequences are cropped to the brain bounding box (with a margin of four voxels), clipped to the 0.5 and
99.5 percentiles of in-brain intensities and z-scored inside the brain; voxels outside the brain are set to zero. The cache
holds, per case, `*_img.npy` (float16, 4 x D x H x W), `*_seg.npy`, `*_fg.npy` (foreground coordinates used for patch sampling)
and `*_meta.json` (grade, bounding box, spacing).

## Splits

`splits.json` contains a **patient-level, grade-stratified** held-out test set (20% by default) and k cross-validation folds over
the remaining patients. `data.assert_no_leakage` verifies that no patient occurs in two partitions; it is run whenever splits are
created. All variants of an experiment use the same splits, so that comparisons are paired by patient.

## Sample data

`data/sample/` contains four tiny synthetic phantoms (32^3 voxels, three HGG-like and one LGG-like) in the BraTS layout, so that
the I/O path can be exercised without access to BraTS:

```bash
bratsgan prepare --root data/sample --cache /tmp/sample_cache --splits /tmp/sample_splits.json --folds 2 --test-frac 0.25
```

They are generated by `scripts/make_sample_data.py` from `bratsgan/synthetic.py` and are **not** medical images.

## Synthetic phantoms

`bratsgan/synthetic.py` generates ellipsoidal "brains" with three tissue classes, four contrasts, a smooth bias field, Rician-like
noise and a nested tumour (necrotic core, enhancing shell, oedema). `difficulty="hard"` uses smaller lesions, thinner enhancing
shells, reduced tumour contrast, blurred labels and stronger noise. They serve to test the code and to study the behaviour of the
training pipeline; they say nothing about accuracy on patient data.
